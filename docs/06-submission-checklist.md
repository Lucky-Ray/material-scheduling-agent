## 2. 本人提交前执行顺序

1. 阅读 README、方案和代码，尤其理解 hard_time、pending、事务与幂等边界。
2. 运行全部测试和示例生成器，检查日志和场景断言。
3. 配置真实模型，使用隔离数据库跑正常、冲突、风险、保存失败路径。
4. 保留真实失败和修复记录；有变化就同步更新评估报告。
5. 填写 AI 使用说明和复盘中的个人事实，不能虚构个人贡献与耗时。
6. 检查不存在密钥、真实隐私数据、题目截图、运行数据库和不必要缓存。
7. 创建自有仓库；如使用私有仓库，按要求授予评审访问权限。
8. 完成提交后执行 `git rev-parse HEAD`，核对提交包含全部材料。
9. 提交题号、仓库 URL 和实际 SHA；交卷前再次检查。

## 3. 当前仍不能打勾的项目

- 真实模型至少两条路径的实际效果验证。
- 对真实模型进行工具结果扰动后的动作复核。
- 真实模型验证之外的业务扩展（审批流程、历史草稿撤回）已明确披露，不计为已实现。
- 候选人亲自完成的修改、实际验证、学习收获与耗时。
- 仓库已公开，不再需要单独授予评审读取权限；交卷时仍要核对最终 SHA。

这些缺口已在文档中明示，不能将本项目称为“所有要求全部完成”。
