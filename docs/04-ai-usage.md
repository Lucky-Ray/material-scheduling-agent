# 04 AI 辅助使用与个人贡献披露

## 1. 披露目的与当前状态

本说明区分“AI 辅助生成”“已实际运行验证”和“候选人本人完成”。候选人必须按自己的真实工作补充，不得直接将 AI 生成内容写为独立手写成果。

本项目初稿及本轮文档补充均由 Codex 根据用户提供的题目截图辅助完成。AI 直接在本地生成、修改并执行工程文件；运行时的业务模型是另一条接入路径，当前未运行真实业务模型。

## 2. AI 辅助范围

| 工作项 | AI 参与方式 | 当前可核对材料 |
| --- | --- | --- |
| 题意理解 | 识别四题任选一题、交付结构、动态决策和验证要求 | 需求文档、提交检查表 |
| 选题与范围 | 选择素材审核排期，收敛到单项草稿链路 | 需求与方案文档 |
| 工程实现 | 生成模型适配、工具、SQLite 保存、执行循环及 CLI | src 各模块 |
| 合成数据 | 编写素材、风险标签、候选和占用时段 | data/catalog.json |
| 测试 | 编写并执行离线测试、故障注入及场景断言 | tests、examples 日志 |
| 文档 | 生成需求、方案、评估、使用披露、复盘与提交检查表 | docs |
| 后续整理 | 项目移出面试目录、拆分代码模块、扩展资料扰动证据 | 独立目录、源文件、场景快照 |

没有从工作区原有项目拷贝业务代码。本项目并不证明候选人先前经历、简历量化结果或真实公司的审核能力。

## 3. 已执行验证与未执行工作

已执行：本地 Python 单元测试、离线场景生成器、CLI 冲突演示；本轮修改后重新执行的结果保存在 examples。每份生成记录均标 mode=mock。

未执行：真实模型请求、实际发布、远端部署、考试提交。GitHub 仓库已由 AI 在用户授权下创建，并按用户要求改为公开；代码上传由 AI 协助执行，结果以远端提交为准。AI 不替候选人确认个人工作时长、个人掌握程度或模型测试结果。

## 4. 两类“AI”的区别

开发辅助 AI 为 Codex，负责帮助编写工程和文档。运行时 Model 通过用户指定 HTTP 服务执行业务动作选择；每步接收业务输入与工具观察。MockModel 为 Python 确定性分支，不是真实模型，也不作为模型效果证据。

不能因为代码由 AI 辅助编写，就声称已满足“真实模型决策循环”的验收。需要额外运行 live 路径并保留记录。

## 6. 建议本人完成的最小复核

1. 逐步讲清 query_slots 如何合并已有排期与草稿占用。
2. 说明为何替代时间必须 pending，以及硬时间为何由工具阻断。
3. 自己跑一次重复请求，核对数据库条数和 draft_id。
4. 自己注入保存失败，核对失败不会变成 completed。
5. 解释载荷级幂等与请求级幂等的差别，判断当前限制。
6. 配置业务模型后检查两条 live Trace，记录不符合预期的地方。

这组复核是建议操作，未执行前不能勾选为本人已完成。

## 7. 数据、密钥和公开材料

本地资料使用合成素材和时段。仓库排除 `.env`、SQLite 运行数据库和 Python 缓存；`.env.example` 只含占位符。运行时仅将业务请求和工具结果发给所配置模型服务，不发送整个面试工作区。

本轮还由 AI 补齐请求级幂等、动作/请求类型校验、聚合结果、CLI 错误协议与离线 CI；这些不计为候选人亲自实现。

当前项目未附带题目截图或完整试卷文本。提交公开仓库前仍应由本人检查资料、真实模型输出及个人信息；私有仓库评审权限与最终仓库地址由本人按实际情况配置。
